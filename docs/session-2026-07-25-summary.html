The deterministic gate passed. The independent reviewer caught it — and the defect was in the contract I wrote, not the implementation. That routes FAIL_CONTRACT: reset and block, because a repair agent cannot fix code into a defective contract.

The lesson, verified by running it

My criterion said “assert these phrases appear in the same section, so the test cannot be satisfied by pasting a string.” The mechanism could not deliver the purpose. Three mutations, each actually executed against the code:

Glossary paste ending “Dispatch does none of this”9/9 passed — not caught
Invert by addition (keeps the phrase)9/9 passed — not caught
Invert by replacement (deletes the phrase)3 failed — caught incidentally

A first amendment tried finer location-binding. It also passed the inversion, and its span was 58 lines wide — swallowing unrelated prose, contradicting its own promise.

Settled reading: a substring assertion cannot detect negation at any granularity. The test is now honestly scoped to placement; meaning is verified by the dry-run and the gate reviewer — a human-judgment surface, which is what goal 003 is about in the first place.

03Where the value came from

The red-team paid for itself before any code ran

Goals 002 and 003 required README/site edits outside their declared touches:. blast_radius fails that, and queue_untouched bars the repair agent from widening it — a deadlock, not a repair cycle. Both would have burned a full implementer run and blocked. I verified it against pg_validate.py:56 and :216 rather than trusting the finding.

It also caught that goal 003's item fires on a PASS — so a “blocker → command” table literally could not hold it. A genuine interface break between 002 and 003, found before either ran.

Two pre-existing contradictions surfaced

The invariant that contradicted the repair path. Four files declared goal files “immutable contracts” while dispatch routed defects to “the human re-specifies via define-goal” in eight places. Narrowed to what it actually protects: immutable to implementers and while claimable.

A promise nothing kept. needs independent review was documented three times and implemented nowhere. Any goal with a subjective criterion had been passing unchecked — in the repo before this session started.

One reviewer finding I overrode

The red-team wanted a version bump per goal. Three bumps for one logical change, dragging plugin.json into every scope list. Made it one owner-performed release instead — and wrote that explicitly into all three contracts so no implementer half-did it.

04Honest notes

What slowed this down

Subagents vs droid exec. The Task tool was unavailable inside spawned implementers in this session, so they reached for droid exec -f to get fresh-context reviewers. That works — the reviews were genuinely independent — but each is a full CLI boot instead of an in-process spawn, which is most of the wall-clock cost. My own orchestrator-level reviews used real subagents.

Two false starts I caught and corrected: a mutation that silently failed to apply (wrong anchor string) briefly looked like a clean pass, and I wrongly assumed a cancelled run had landed no work — it had committed 96ddda9 and was complete. Both were caught by re-checking rather than trusting the first read.

Known drift, deliberately unfixed: dispatch and factory-doctor both claim dispatch runs the doctor probe every fire. It does not. Harmless today — and it is what makes goal 001's cost acceptable — but it is documentation asserting a safety behavior that does not exist. Recorded in the brief.
